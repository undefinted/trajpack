# Cluster H100 utility smoke replication (2026-08-20)

[English](cluster-h100-20260820.md) | [简体中文](cluster-h100-20260820.zh-CN.md)

This is a real, strict-offline cluster run on one NVIDIA H100 PCIe GPU. It
independently replicates the direction of the local RTX 4060 result for this one
synthetic calculator protocol. It is **not** evidence that trajectories are
universally better or that hidden model reasoning was recovered.

| Arm | Tool JSON | Exact expression | Executable outcome | Final accuracy | Tool-using E2E |
| --- | ---: | ---: | ---: | ---: | ---: |
| Base | 0/32 | 0/32 | 0/32 | 0/32 | 0/32 |
| Answer-only SFT | 0/32 | 0/32 | 0/32 | 1/32 | 0/32 |
| Complete trajectory SFT | **32/32** | **27/32** | **31/32** | **31/32** | **31/32** |

On the same input files, model revision, seed, and 60-step configuration, the
complete action → observation → answer view produced valid executable tool calls
on all 32 held-out tasks and completed 31 end-to-end. Answer-only SFT learned no
tool use and answered 1 task correctly. The earlier RTX 4060 run reported
32/32 versus 0/32 tool-using E2E, so the qualitative result survived a different
GPU, PyTorch/CUDA stack, and fresh offline execution.

The two runs are not bitwise replicas: their experiment source-tree hashes
differ, including the missing-`git` robustness fix used on the cluster. The
comparison is therefore a directional engineering replication, not a claim of
cross-hardware deterministic equivalence.

## Adjacent raw-to-export check

The existing synthetic DeepSeek Harness demo was regenerated before this run.
Its complete raw → canonical → privacy/quality → approval →
`deepseek_epoch_sft` artifact tree was copied to the same cluster persistent
volume. All 20 root-manifest entries and all 10 HF/TRL checksums passed there,
including:

- JSONL: `2594bc5c25d0e9c3c31449b12ac21938c8b9f3abb0cd02ce133a02295fa4a341`
- native Parquet: `dd480380ea63060fe641cbc0bf7994fd3119db17258d695557c3681b9faddfca`
- lineage: `1337d0f6a2ab315b2bda126fe6f8a864e51dfa1bbb8bed672a0f672f6bf2d3ae`

This proves that the reviewed export artifacts transfer intact across machines.
It does **not** make them the input to the utility run above: that run used the
calculator fixtures with hashes listed in its manifest. A faithful end-to-end
trainer still needs a versioned renderer for top-level tool schemas,
`reasoning_content`, and component-level `training_targets`; silently dropping
those fields would not count as success.

## Failures retained during bring-up

The run exposed three useful engineering faults rather than hiding them:

1. The cluster replaced chart `alpha` with `med` and changed the GPU values
   schema. The first rendered pod was CPU-only; CUDA checks rejected it before
   training.
2. The pod cannot reach Hugging Face. A complete pinned snapshot was copied from
   local cache, its weight hash was verified, and the successful retry was
   strictly offline.
3. The minimal image has no `git` executable. The runner now treats this
   optional provenance field as unavailable while retaining its deterministic
   source-tree hash; a regression test covers this case.

Each retry used a new output directory. No partial result was reused as a
success.

## Important limits

- This remains a single-seed synthetic protocol smoke test.
- The complete arm saw 6,806 target tokens versus 4,140 for answer-only
  (+64.4%). It therefore demonstrates learnability and pipeline feasibility,
  not a controlled causal effect of trajectory structure alone.
- These training fixtures already use trajpack's `DatasetExample` contract, but
  this run did not train on captured production DeepSeek Harness sessions.
- The next credible utility study is target-token-matched, multi-seed, and uses
  owned repo-disjoint coding tasks with executable held-out tests.
